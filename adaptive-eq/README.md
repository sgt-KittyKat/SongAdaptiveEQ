# AdaptiveEQ

Steps 2 through 5 of the hackathon plan: a local audio player, measured headphone EQ, background track analysis, and experimental track-dependent correction with verified sample peaks. Loudness-matched randomized listening is the next milestone.

## Run on this computer

Double-click `Start-Player.cmd` in the parent folder, or run `Start-Player.ps1` from PowerShell. The launcher uses an installed Node.js or the bundled Codex runtime, starts the local Vite server, and opens the app. Keep the terminal running while using the player; Ctrl+C stops it. If port 5173 is busy, Vite prints and opens the next available port.

With Node.js 24+ and pnpm 11.25.0 available:

```sh
pnpm install
pnpm dev
```

Use the Local URL printed by Vite, normally `http://127.0.0.1:5173/`.

## Use

- Choose or drop one mono/stereo WAV or MP3, up to 5 minutes and 64 MiB.
- Click Play. Importing a file never starts playback automatically.
- Click or drag across the waveform to seek. Use the 10-second transport buttons for larger jumps.
- Adjust volume or mute; unmuting restores the previous volume.
- Use Space to play/pause and Left/Right arrows to move 5 seconds when focus is outside an interactive control. Sliders retain their native keyboard behavior; Home/End seek to the exact start/end of the track.
- Use Remove or Cancel to clear a loaded or pending track.
- Try a sound check creates an original synthetic 16-second WAV locally.

Files are processed in the browser and never uploaded. Fonts are served locally. The waveform comes from decoded channel peaks. The displayed sample rate is the playback/decode rate, which may differ from the original file's sample rate because Web Audio resamples to the audio context.

The system's current output device is used; choose the physical output in Windows. Selecting a headphone profile changes the EQ, not the Windows output device.

## Headphone correction

1. Load a track and select **SteelSeries Arctis 7+** in the headphone section. The exact Arctis 7+ is supported; Arctis 7, 7P+, and Nova variants are different profiles. Turn off additional vendor EQ, surround/spatial effects, and other audio enhancements before evaluating correction.
2. The player applies the ten-filter AutoEq preset after an offline sample-peak check. The initial selection is **No correction / other headphones**, so a profile is not silently applied to an unknown device.
3. Switch **Bypass / Corrected / Adaptive** during playback. Forty-millisecond linear gain fades change the processing without replacing the playing source. All modes retain the same safety trim. This comparison is not LUFS/loudness matched.
4. The dashed **Headphone** and teal **Combined** curves show measured correction and measured-plus-song response before trim; the lime **Applied + trim** curve shows the active mode's net EQ/preamp response, before user volume. Bypass is flat at the shared trim. Inspect frequencies with the pointer or the graph slider's arrow keys. During a check, the graph retains the last verified combined response.
5. Expand the settings disclosure to see the ten imported filters, the exact pinned source, original preset, and license.

The Marshall Major V is explicitly unavailable until an appropriate exact-model numerical profile is sourced. No other Marshall generation's settings are substituted.

The preset is generated by [AutoEq](https://github.com/jaakkopasanen/AutoEq) from RTINGS measurements on the HMS II.3 over-ear rig. Its numerical settings are in `src/data/arctis-7-plus.json`. The upstream preset text and AutoEq MIT license are preserved in `public/profiles/` and `public/licenses/`. Provenance includes a pinned repository commit and SHA-256 checksum. Only the generated filter preset is bundled, not RTINGS raw measurements or plots. `node scripts/import-profile.mjs` intentionally refreshes this data from upstream and requires network access; ordinary use of the app does not.

The source preset text specifies -5.2 dB preamp; its accompanying upstream README showed -5.3 dB when inspected. The app preserves the text-file settings and independently calculates its own, more conservative headroom.

## Experimental track adaptation

Select **Adaptive**, choose Balanced/Warm/Clear, then adjust **Song blend** from 0–150%. Default 100% now uses the expressive robust engine; zero routes through the measured chain exactly. The measured headphone preset stays verbatim. A separately fitted song layer supplies up to eight broad filters. The graph exposes **Song only**, **Headphone**, **Combined**, and **Applied + trim**, with verified reference family, spectral support, and fitting diagnostics.

The previous engine discarded within-band differences by reducing eight averaged bands to five fixed filter regions. It ignored temporal median/variation and hard-clamped many different deviations to the same ±3 dB values. Its fixed percentage gates also suppressed useful low-energy regions. Global level normalization was necessary; pooling, unused temporal information, generic targets and saturation were the main losses.

The worker now retains 30 one-third-octave regions from 16,384-sample Hann FFTs (2.93 Hz spacing at 48 kHz). Each frame is normalized by its total spectral power, so louder sections do not receive extra votes. Each band's representative power combines a 10% two-sided trimmed mean (65%) and median (35%), then one global normalization. Occupancy, 20th–80th-percentile spread and FFT resolution estimate reliability. Quantile peak/valley contrast distinguishes tonal within-band detail from broad deviations. A robust median pairwise slope reports power-per-octave tilt. Original eight-band statistics/timeline remain available; version-2 JSON adds the detailed summary. Version-1 summaries remain supported through a coarse adapter.

Balanced/Warm/Clear are designed power-per-octave reference preferences (-0.2/-1/+0.6 dB/octave with extreme-frequency rolloff), not learned genres or optimal mastering standards. Measured regional contrast selects a modest Bass-rich, Bright, Dark, Mid-focused or Presence-led family allowance of up to 1.5 dB. This retains some broad character instead of forcing every track to the same target. Presence-led means spectral emphasis in the vocal range, not detected vocals. A single weighted median removes overall level only; tilt and regional differences remain.

The goal uses confidence-dependent tolerances (0.6–1.5 dB), deviation-dependent strength, broad octave smoothing, and soft saturation rather than an early hard clamp. Reliable, persistent broad local features contribute; high-contrast harmonic detail and unsupported holes are not chased. Boosts require temporal support and a meaningful signal floor, replacing the old fixed 0.5%-of-track-power gate. Sparse tonal material falls back to measured EQ. Small or unreliable deviations can legitimately produce little change. Reference guidance follows the broad-shape principle described in [iZotope's EQ matching documentation](https://downloads.izotope.com/docs/ozone8/equalizer/index.html); quantile peak/valley contrast is described in [librosa's spectral contrast documentation](https://librosa.org/doc/main/api/generated/librosa.feature.spectral_contrast.html). Our parameters, families and confidence rules are independent prototype choices.

A native-response coordinate fit accounts for filter overlap. Shelves handle tilt; up to six broad peaks are placed at supported residual features, with Q 0.55–1.35. The fitter reports weighted response error so smoothing/fitting losses remain visible. Filters and the complete song layer stay within ±5 dB, checked on 4,098 frequencies including DC/Nyquist. Gains are not forced to a minimum. Strength can reach 150%, while the same final bounds apply. Whole-track native peak rendering verifies the combined headphone-plus-song chain before installation. Requests serialize/coalesce; stale results cannot overwrite the current track or setting; failures retain verified playback and offer retry.

See [SONG_EQ_VALIDATION.md](SONG_EQ_VALIDATION.md) for old/new responses across nine controlled contrasting passages. These demonstrate implementation behavior, not listener preference. Real-music listening at matched loudness remains Step 6.

## Headroom behavior

The initial preamp is the most conservative of zero, the imported preset preamp, the maximum combined filter boost plus 1 dB of margin, and the original sample-peak requirement. The response bound uses a dense frequency grid including DC/Nyquist; for this preset it yields approximately -7.7 dB, more conservative than bounding only the plotted 20 Hz-20 kHz range.

For each decoded track/profile pair, the player renders the exact filter chain through `OfflineAudioContext`, including a half-second tail. It scans the complete rendered signal, then adds attenuation if either corrected or bypass samples would exceed -1 dBFS. The UI reports these checked peaks before the user volume gain. Verified results and in-flight renders are reused when toggling modes/profiles. Stale renders cannot activate an old correction. If verification fails, the player falls back to bypass with an error and allows retry.

These are digital **sample-peak** checks for full-track playback from the beginning, not a true-peak limiter or a guarantee about every seek transient, reconstruction overshoot, acoustic level, distortion, or the physical headphone's output capability. Profiles are model-average estimates, affected by unit variation and fit.

## Track analysis

Loading a track automatically starts a background worker that analyzes its original decoded PCM, before EQ, safety trim, and volume. Playback stays available while it runs. Use **03 Track analysis** in the section navigation to view progress and the completed result. **Cancel analysis** terminates the worker; **Analyze track** restarts it. Errors have their own retry control and do not disable playback. Replacing or removing a file cancels the old job and discards stale messages. One completed summary is retained per loaded track, independently of headphone selection, bypass, and volume.

The panel provides:

- Eight broad regions: 20-60, 60-150, 150-400, 400-1000, 1000-2500, 2500-5000, 5000-10000, and 10000-20000 Hz. Regions are clipped to the decoded Nyquist bandwidth; unavailable regions are marked.
- Relative band energy, band activity, and advanced median/variation statistics.
- A timeline of up to 64 sections spanning the full recording, inspectable by pointer or keyboard.
- Source RMS in dBFS, source sample peak, waveform crest factor, and analyzed-frame counts.
- **Save analysis**, which downloads the numeric summary as JSON without PCM audio.

The worker uses Meyda 5.6.3 power spectra, 16384-sample Hann windows, 8192-sample hops, fractional band-edge bin weights, and independent channel powers. It removes each channel's whole-track DC mean for spectral analysis. A first level pass excludes frames more than 60 dB below the strongest frame's RMS. FFT input is scaled by the recording's peak for numerical stability; relative energy/activity features remain invariant under uniform source gain. Original RMS and crest still use the unprocessed, ungated samples.

Energy percentages integrate power across each broad band, not power per hertz. Band activity counts analyzed frames where that band contributes at least 1% of the combined measured band power. Variation is the standard deviation of frame shares in percentage points. The silence gate and activity threshold are design choices, not psychoacoustic audibility thresholds. Neither RMS nor crest is LUFS or a complete measure of musical dynamics. Very short clips have limited frequency detail. Silent/DC-only inputs return empty spectral summaries safely.

These measurements describe content; they do not identify instruments, diagnose mastering faults, or decide what sounds better. Headphone calibration stays independent of the song. The detailed robust summary drives the separate song layer.

The original playback buffer remains intact: the client copies PCM into transferable worker-owned arrays, and terminates the worker after completion, error, or cancellation. The five-minute/64 MiB import limits also bound this memory allocation. The production build packages a dedicated worker asset; it has no analysis backend or network requests. Vite pre-optimizes Meyda during local development to avoid a dependency-discovery reload on the first track.

## Architecture

- `src/audio/AudioEngine.ts`: one lazy AudioContext, decoded buffer, one active source, transport, profile/mode state, rendered peak verification/cache, subscriptions, and import/cancellation handling.
- `src/audio/equalizer.ts`: filter construction, shelf coefficients, combined response measurement, headroom calculations, offline peak rendering, and three crossfaded playback paths.
- `src/audio/adaptive.ts`: content-aware reference families, confidence-weighted song goals, fixed headphone calibration and fallbacks.
- `src/audio/spectral-analysis.ts`: detailed robust temporal statistics, contrast, tilt and smoothing.
- `src/audio/song-fitting.ts`: native-response filter placement/fitting and combined-response limits.
- `src/HeadphonePanel.tsx`: exact-model selection, three modes, strength, comparison graph, numerical explanations, peak readouts, and source/filter details.
- `src/audio/analysis-model.ts`: versioned summary types, bands, and analysis constants.
- `src/audio/track-analysis.ts`: testable PCM analysis, independent of playback.
- `src/audio/analysis.worker.ts` and `analysis-client.ts`: worker progress, PCM transfer, errors, and termination.
- `src/TrackAnalysisPanel.tsx`: statistics, frequency distribution, section timeline, method details, and JSON export.
- `src/audio/demo.ts`: original generated PCM WAV for trying playback.
- `src/App.tsx`: file handling UI, real waveform, transport, keyboard shortcuts, and error states.
- `src/styles.css`: responsive layout, local fonts, and reduced-motion support.

The audio graph is `source -> input -> shared preamp -> [dry OR measured filters OR verified adaptive filters] -> volume -> destination`, with a gain on each branch. Replaced adaptive branches crossfade out before disconnection. Peaking bands use native BiquadFilterNodes. Shelves use IIRFilterNodes with RBJ coefficients to honor the imported Q of 0.70; Web Audio's native shelf BiquadFilterNodes ignore Q. Graph measurements call `getFrequencyResponse()` on those actual filter nodes. Decoded PCM stays outside React state.

The shared trim is the most conservative verified requirement across measured and adaptive output. It never relaxes while changing adaptation on a loaded track, so a previously verified branch remains protected during its fade. Zero strength and Corrected still use identical processing at that same trim. Selecting another profile or loading a new track starts a fresh headroom calculation. This is sample-peak checking, not a true-peak limiter or loudness matching.

Metadata is checked before allocating decoded PCM to reject long compressed recordings early. Decoded duration and channel count are checked again. Replaced/cancelled loads cannot overwrite the latest selection. Pause, seek, and track changes stop and disconnect the old source before starting another.
